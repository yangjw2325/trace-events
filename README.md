# 溯源 · 投资事件与证据时间线

面向需要持续跟踪上市公司事项的投研用户，把分散的公告与资讯组织为事件、证据与判断版本，让用户核对“发生了什么、依据是什么、后来哪里变了”。

- 产品：https://trace-events.vercel.app
- 源码：https://github.com/yangjw2325/trace-events
- 体验：点击“登录”直接进入测试账号，无需手机号。身份按浏览器会话隔离，不是实名账户。
- 仓库当前为私有；提交前需开放评审访问。离线源码包与仓库采用同一份正式代码。

## 建议体验路径

1. 搜公司“海尔”，进入海尔生物总览，再进入吸收合并事件，查看从筹划到终止的演化及关联公司。
2. 展开具体材料，核对事实陈述与原文引证；“查看原文”打开公告，“定位证据”定位站内对应材料。
3. 搜公司“贵广”，进入年度更正相关事件，对照更正前后字段及历史版本。终止是后续进展，更正是修正既有说法，两者分别处理。
4. 关注公司或事件；后续相关新事件或重要变化进入“变化通知”。首次关注不补发旧消息，进入公司不清未读，打开具体事件只清除该事件截至展示版本的提醒。

线上不会为展示凭空生成更新通知；通知闭环另有事务测试和历史回放证据。

## 核心设计

搜索入口区分公司与事件；联想只补全输入，搜索结果才进入详情。事件归并围绕具体事项与说法，不把同公司所有消息归成一个事件。一份材料中的不同传闻可以关联不同事件。

阅读分三层：简短现状、按事实／观点／推测／传闻分类的说法、按需展开的逐字原文。明确期间和单位的财务事实用表格展示，歧义数据保留文本。事实标签表示陈述类型，不保证内容已经证实；新闻转述不能替代原始公告。证据采用来源、全文／片段、可核验引用及关系校验约束，不输出未经验证的统一可信度分数。

事件时间、披露日期、抓取时间和判断生成时间分别保存。来源只有日期时保留日级精度，不编造披露时刻。判断与原文按版本留存，后续进展、更正或否认不覆盖旧版本。

## AI 角色

开发协作中，AI辅助需求整理、原型、编码、数据核验和测试；候选人确定用户路径、MVP范围、交互与已读规则，并逐轮审阅。

产品内使用DeepSeek执行两阶段分析：先抽取带原文引用的分类说法，再结合已入库历史判断是否同一事件、是否发生重要变化。程序检查JSON结构、引用连续子串、更正目标和版本一致性；不通过的材料进入待核验，不直接发布。校验通过表示满足这些程序规则，不等同于语义事实已全部正确。

## 数据与运行

已收录海尔生物、上海莱士、贵广网络。iFinD提供公告线索与资讯检索；巨潮权威PDF补齐公告原文；扶摇用于行情快照留存，目前不自动给出价格因果解释或投资建议。新闻片段与公告全文分开展示。

Next.js网站部署在Vercel；Supabase PostgreSQL和私有存储保存事件、版本、原文及关注。GitHub Actions计划每天北京时间09:00采集与分析，可能有平台调度延迟。当前按已收录公司检索最近3个自然日，不能视为全市场完整覆盖。密钥仅配置于服务端。

本地运行（Node.js 24）：

```bash
cd app
npm ci
npm run build
npm run start
```

访问http://127.0.0.1:3100。环境变量参考根目录`.env.example`与[技术方案](docs/技术方案-MVP.md)，云端能力需要自行配置服务凭证，不附带真实密钥。更多命令见[应用说明](app/README.md)。
