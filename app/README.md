# 溯源 Web 应用（本地实现）

基于已确认原型实现 Next.js + React 页面，使用真实的历史公告数据。

## 运行

要求 Node.js 24+。在本目录运行：

```bash
npm ci
npm run build
npm run start
```

打开 http://127.0.0.1:3100 。开发时可使用 npm run dev。

## 已接通

公司/事件搜索、联想补全、相关性与日期排序、公司总览、单事件时间线、原文引用、证据概览定位、留存PDF、历史版本、浏览器独立体验会话、关注与阅读进度。

数据文件 data/dataset.json 由 scripts/export_web_dataset.py 从核验原文和模型回放结果导出。海尔事件判断来自顺序模型回放，贵广材料关系与展示经过人工核验。同一风险提示公告中的不同传闻分别建档。

存储由 STORAGE_DRIVER 选择：sqlite 为本地模式，postgres 为Supabase云端模式。当前工作区已切至云端，关注和阅读进度写入PostgreSQL，原文通过私有存储读取；Cookie使用服务端会话密钥签名。历史回放数据库保存在工作区 references/verified-originals/。首次关注自动创建体验身份，头像也可创建身份。

## 当前进度

- 当前网页读取已核验历史数据；搜索不会调用模型。
- 采集发布与站内通知已接通：新事件或重要变化在同一事务保存版本和通知，同时关注公司与事件只通知一次。历史回放测试通知不导入真实体验用户。
- Supabase托管数据库及私有原文存储已接通；每日调度由GitHub Actions承担，上线状态以云端任务记录为准。
- 交易所原始分类尚待补齐，当前分类标记为系统分类。
- 生产部署使用 postgres 配置，PDF与资讯片段保存在私有云存储；SQLite仅用于本地回放。

## 采集与通知

```bash
npm run jobs:daily
npm run jobs:resume
npm run jobs:automated
```

每日任务检索已收录的3家公司最近3个自然日公告与iFinD资讯，并记录扶摇行情快照。公告原文来自巨潮官方PDF，iFinD返回的资讯保留为片段，页面区分全文和片段。原始文件以SHA-256留存，模型只处理新内容。两阶段模型分别抽取带逐字引用的说法、判断事件归并和变化；校验失败或归并不明的材料留待核验，不自动发布。

云端每日任务使用 jobs:automated：先检索入队，再自动顺序处理最多40份材料，总处理预算25分钟。剩余数量展示在数据状态中。网络或并发错误最多重试3次，跨运行保留；证据校验失败保留待核验。处理租约超时后可恢复，重复原文不会再次发布或通知。同日已完成采集会跳过；部分失败可重新运行。

通知只发给已经关注相关公司或事件的体验用户；页面每60秒及恢复窗口焦点时刷新。不会为新关注者补发关注前的历史变化。旧判断与原文版本不可覆盖；没有重要变化只关联证据。

网站由Vercel托管，Root Directory为app，Node.js 24，区域pdx1与数据库相近。后台任务由私有仓库的GitHub Actions执行，UTC 01:00（北京时间09:00）计划启动；平台高负载可能延迟。支持workflow_dispatch手动验收和失败重跑。Vercel不再重复调度。配置服务端环境变量及Actions Secrets，验证成功后设置 CRON_SCHEDULE_ENABLED=true；真实密钥不提交代码仓库。现有Cron HTTP入口仍要求CRON_SECRET鉴权。

模型核验无法替代人工事实判断；待核验队列目前通过数据库及命令查看，未新增产品审核页。交易所分类映射、来源失效后的持续探测和超出查询窗口的补采尚未实现。
