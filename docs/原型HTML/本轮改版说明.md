# 登录、证据阅读和关注通知：原型评审稿

日期：2026-11-02。此文件记录已确认的原型方案；正式实现按PRD v0.4与技术方案同步。原型中的样例仍与真实数据隔离。

## 1. 登录

未登录时，右上角显示“登录”按钮。点击即进入当前浏览器的测试账号，按钮切换为“研”头像；点击头像可看到“测试账号”。不增加注册、手机号、密码或第三方登录流程。

保留原有关注的免注册行为：未登录直接点击关注时，一次完成进入测试账号与关注，顶部同步显示账号状态。

## 2. 摘要、说法与原文分层

| 层次 | 显示内容 | 默认状态 |
| --- | --- | --- |
| 顶部事件摘要 | 一句现状与少量关键字段；新闻案例显示当前依据及待补材料 | 展开 |
| 时间线材料 | 来源、标题、日期、各类说法数量；展开后按事实陈述、观点等分类 | 默认收起；“查看依据”“定位证据”会展开 |
| 对应原文引用 | 逐字引用及页/段位置，和对应说法绑定 | 点击该项“查看引用”后显示 |

减少重复的方式：摘要不复制完整数据与机构观点；同类型说法合并分组，避免每一句前重复分类标签；逐字原文不与提取结果同时铺开。

财报类事实使用指标表格；普通公告按具体字段或短句呈现。表格是这个案例的展示形式，不要求所有事件都做表格。观点仍归属于具体发布主体，不写成产品确认的事实。

“事实陈述”表示材料的陈述方式；另行显示“新闻转述”和事件核验状态。新闻片段不伪装成公司公告。原文位置使用自然语言，文件指纹等放在材料信息中。

## 3. 关注后的新增与变化

- 关注公司：接收该公司新增事件，以及已有事件的重要变化。
- 关注事件：接收该事件的重要变化；不因为同公司出现另一事项而提醒。
- 首次关注以当时版本为起点，不补发旧消息、不立即显示“有更新”。
- 关注之后同一变化只生成一条通知；同时关注公司与事件时，在通知中注明合并提醒。
- 首页保留标题、日期及“有更新”；不增加长摘要。
- 我的关注：公司条目显示未读更新数，并列出“新增”和“更正”入口；事件条目显示“有更新”。
- 变化通知：区分“新增事件”和“事件变化”。新增事件显示一句发生了什么；变化显示受影响字段的旧值→新值、版本与依据。
- 新增通知进入新事件；变化通知直接进入历史版本对照，并可定位触发证据。

### 已确认的阅读规则

用户已确认按具体事件的变化统一维护未读：打开对应事件后，该条通知与公司/事件关注提示同步已读，其余变化保留。

进入公司总览本身不清空该公司的所有未读。相较旧PRD“进入公司即可标记当前变化版本”，此行为已确认，正式应用与PRD按本规则实施。

通知列表本身不自动全部标已读。取消关注停止后续提醒，已有通知保留。

## 4. 演示方法

原型入口：review.html。页面底部的“原型演示”区域仅用于评审，不是拟新增的产品功能。

1. 未登录首页：点击登录，查看账号变化。
2. 搜索云川科技，关注公司；同时关注“收购星河半导体”事件。
3. 打开我的关注：有关注记录，没有未读提示；变化通知为空。
4. 点击“模拟下一次更新”：新增定增事件、收购金额由10亿元更正为8亿元；收到2条通知，而非3条。
5. 查看收购更正：直接进入V1→V2对照，返回后只剩新增事件未读。
6. 查看新增事件：关注和通知的未读标记全部消除，通知历史保留为已读。

原型继续使用虚构公司及材料，不调用真实接口、不生成实际站内通知。

## 5. 已核验

- Chrome实际点击：未登录显示登录，一键进入测试账号。
- 财务数据表格默认不显示逐字原文，点击引用后只展开对应原文。
- 同时关注公司和事件，首次关注不生成历史消息。
- 模拟更新得到2条通知，新增与更正分别展示。
- 打开更正后，未读数由2变为1，事件“有更新”消失，公司保留新增事件的1条未读。
- 原型阶段曾校验实际应用与PRD保持不变；方案认可后，正式实现按本规则更新。
