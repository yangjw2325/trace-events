## 异常与访问边界

| 场景 | 已验证行为 |
| --- | --- |
| iFinD嵌套JSON、备注、空结果、业务错误 | 分别解析；权限／工具失败不能记作成功无结果 |
| 模型引用补字或更正目标不存在 | 拒绝发布；不覆盖已有判断 |
| 新闻片段直接确认关键状态 | 转待核验，不仅凭片段升级为确定结论 |
| 网络／并发失败、租约超时 | 最多三次重试、过期租约可恢复；待核验与瞬时错误分开 |
| 重复材料、旧版本并发提交 | 内容去重；过期版本提交被拒绝；不重复通知 |
| 用户隔离与跨来源请求 | 签名会话隔离关注；跨来源写请求拒绝；非法版本拒绝 |
| 未授权定时接口 | 返回401；真实密钥不进入客户端或源码包 |
| 非权威／内网PDF地址 | 拒绝内网地址及不符合官方地址约束的下载目标 |

以上访问与来源检查不是完整渗透测试，也没有验证所有提示词注入场景。产品不开放用户上传新闻／证据的UGC入口；外部文本仍可能包含错误或恶意内容，当前通过结构、引用、来源和发布条件约束，未声称消除投毒风险。全文／片段、来源与未核实状态在页面分别展示；供应商使用与再分发权限不能由技术连通性验证替代。

## 复现方式

在`app/`运行：

```bash
npm ci
npm test
npm run build
```

启动服务后可执行：

```bash
TRACE_TEST_URL=http://127.0.0.1:3100 node --test tests/http.test.mjs
```

配置自己的云端环境后执行：

```bash
TRACE_CLOUD_TEST=1 node --test tests/cloud-*.test.mjs
```

云端用例需要样本事件与相应数据库结构；应在自有测试项目执行，不把可运行命令视为无需凭证。历史JSON报告为本次作业原始记录，重新运行模型不保证逐字一致。
