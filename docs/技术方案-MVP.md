# 投资事件情报与证据时间线：MVP技术方案

日期：2026-11-02。依据：PRD v0.4及已确认交互原型。

## 1. 结构与已选服务

实现使用JavaScript、Next.js 16、React 19、Node.js 24。Vercel托管网页与API，Supabase PostgreSQL保存事件和用户状态，私有对象存储保存公告PDF与资讯片段。GitHub Actions承担每日采集与分析，目标北京时间09:00启动，平台可能延迟。

浏览器读取已保存的数据，搜索、排序、返回和原型一致，使用已加载的数据完成本地切换。当前范围是已收录的三家公司；不在每次搜索时调用模型或重新采集。

```text
浏览器 → Next.js页面、API → PostgreSQL / 私有对象存储
GitHub Actions每日任务 → 巨潮原文、iFinD检索、扶摇行情
                    → DeepSeek抽取 → 事件归并和变化分析
                    → 引用与目标校验 → 事务保存版本及站内通知
```

## 2. 页面与实际接口

| 页面或接口 | 用途 |
| --- | --- |
| `/` | 标题、公司/事件搜索、各半的关注与推荐列表 |
| `/search?type=company或event&q=...&sort=...` | 相关性或日期排序，返回主页与搜索框同行 |
| `/companies/:id` | 相关事件、关注公司、更新信息；进入页面不清除未读 |
| `/events/:id` | 短事件摘要、单主时间线、证据概览、历史版本 |
| `/following`、`/notifications` | 关注分组、更新入口、新增/变化通知及未读 |
| `GET /api/data` | 公司、事件、材料版本、说法、当前会话的关注与通知 |
| `POST /api/actions` | `session`、`follow`、`unfollow`、`read` |
| `GET /api/source/:id?hash=...` | 代理读取指定哈希的私有原文快照 |
| `GET /api/cron/daily` | 保留的受CRON_SECRET保护的任务入口；线上不重复配置Vercel Cron |

搜索结果和返回路径使用站内来源参数；普通导航和排序不等待新的服务端页面请求。历史变化通知携带事件、版本及历史版本页签，原文定位保留具体材料哈希。

`/api/actions`的用户来自签名会话，不接受浏览器指定其他用户ID。写请求检查Origin、JSON类型与长度。`read`只接受`kind=event`、存在的事件及不超过当前事件版本的非负整数；公司级批量已读请求返回400。

## 3. 登录与未读规则

右上角未登录显示“登录”，点击`session`即进入测试账号。服务端生成随机用户ID，通过签名的HttpOnly、SameSite Cookie保存；HTTPS环境设置Secure。首次直接关注同样可建立测试会话后完成关注。不同浏览器的状态隔离，不增加手机号、密码或跨设备账号流程。

未读由该用户实际收到的通知计算，不再用公司所有事件的版本总和。响应中的关注对象附带`unread`及`unread_count`，由同一组未读通知派生。

新通知保存命中的关注关系及关注创建时间`follow_reasons`。重新关注建立新起点，旧通知历史仍可查看，但不作为新订阅的未读更新。旧通知缺少该元数据时，按事件关联及生成时间兼容计算，不回填或改写历史判断。

进入公司总览、关注页或通知列表均不写已读。打开事件时，前端捕获本次显示的版本并调用事件级`read`；服务端标记该事件、不超过该版本的通知已读。公司与事件的提示从通知重新计算，其余事件不受影响。轮询到更高版本不会自动清除刚到达的新变化。较低版本的后续请求不会使阅读进度倒退。

网页每60秒及恢复窗口焦点时刷新；写操作与轮询使用序号避免较早的读取结果覆盖刚完成的已读或关注操作。

## 4. 摘要、材料与引用

事件详情保持三层：

1. 事件摘要：一句现状及少量依据字段；从现有状态和保存的摘要提取短句，不截断数字或单位、不补造结论。新闻片段且待核实时说明需要原始材料，完整判断在历史版本中保留。
2. 材料内容：默认收起，定位时展开；按事实陈述、观点、推测、传闻分组，不逐句重复分类标签。
3. 原文引用：每项按需展开逐字引用与页/段位置；完整提取文本和技术信息另行折叠。

财务表格仅整理能够明确识别期间、营收、归母净利润及单位的事实说法，保留增减方向和补充指标；有未能无歧义对应的数字时保留短句展示，不强制转表格。分类是来源材料的陈述方式，新闻转述与核实状态分别展示。

引用按材料哈希和段落ID匹配，历史引用不会落到当前材料的其他版本。更正对照由明确关系记录生成，保留受影响旧说法和更正依据；来源原文与定位证据为两个独立入口。

## 5. 数据与发布事务

沿用现有`trace_`表，无须为本轮交互增加表或修改旧版本：

| 表组 | 用途 |
| --- | --- |
| `trace_companies`、`trace_events`、`trace_event_companies` | 公司、事件身份、当前版本及关联 |
| `trace_documents`、`trace_document_versions`、`trace_claims` | 材料当前指针、不可覆盖版本、逐字引用 |
| `trace_event_versions`、`trace_event_evidence`、`trace_claim_relations` | 判断历史、证据版本与更正/否认等关系 |
| `trace_changes`、`trace_notifications` | 重要变化及用户通知，用户/事件/版本组合唯一 |
| `trace_users`、`trace_follows`、`trace_reads` | 浏览器测试身份、关注起点、事件阅读进度 |
| `trace_queue`、`trace_fetches`、`trace_analysis_cache`、`trace_daily_jobs`、`trace_runs` | 队列、来源访问、缓存、任务与异常记录 |
| `trace_metadata` | 数据覆盖及任务状态 |

数据库RLS禁止浏览器角色直接读写；只有服务端访问。材料和判断版本有禁止更新/删除的触发器。读取当前数据不改变历史版本。

更新事务同时写说法、关系、判断版本、变化记录和通知，并校验预期版本号。同一用户关注多个相关对象时用分组写入一条通知。新通知JSON补充`notification_type`、`company_ids`、`event_title`、前后状态、明确的字段差异，以及实际命中的`follow_reasons`；现有记录继续兼容读取。

新增事件通知进入事件详情；变化通知优先显示字段旧值→新值、版本及触发来源，未提供结构化差异时使用状态或历史判断对照，不推断变化字段。普通证据补充不产生重要版本和通知。

## 6. 每日采集与模型

自动任务由私有仓库`.github/workflows/daily.yml`注册，支持每日计划和手动执行。先采集入队，再顺序处理；单轮最多40次材料尝试、处理预算25分钟。可重试的网络或并发错误最多尝试3次；租约过期可恢复。引用不匹配或归并不明确的材料留待核验，不发布为确定结论。

iFinD使用MCP查询公告及资讯；检索片段与公告全文分开记录。巨潮提供权威PDF补齐；扶摇行情单独保存任务快照。查询覆盖当前三家公司、最近三个自然日，公告单次最多30份、资讯各3条；截断和来源失败写入部分完成状态。

DeepSeek阶段A抽取说法和逐字引用，阶段B提出事件归并、关系及变化。harness检查ID、引用位置、受控状态和更正目标，再事务提交。材料哈希、提示词及输入上下文组成缓存键，未变化输入复用结果。模型只处理采集任务，搜索和浏览不调用模型。

四种时间分开：发生时间、披露时间、获取时间、版本生成时间。日级来源日期保留精度，不补造时分秒。材料保存在私有桶`trace-originals`或`trace-text-snapshots`。

交易所完整分类映射、超出窗口的补采及来源失效持续探测仍按上线记录列出实际进度，不因本轮界面更新宣称已实现。

## 7. 部署与验收

生产地址：https://trace-events.vercel.app 。Vercel根目录app、Node.js固定24.x、函数区域pdx1；Supabase连接使用官方CA验证TLS。服务端密钥只放平台环境变量及Actions Secrets，仓库保留空值示例。

代码通过用户私有GitHub仓库保存，当前采用Vercel CLI部署；每日后台任务独立运行。数据库读取接口和旧通知保持兼容，本轮不覆盖历史判断、不制造线上演示通知。

验收覆盖：登录按钮一键进入测试账号；默认不铺开引用；财务表格数字/单位/增减方向准确；首次关注无旧更新；公司页保留未读；逐事件清除所有相关入口提示；另一事件未读保留；并发更高版本未被较早阅读请求清除；取消和重新关注不复活旧订阅更新。

本地SQLite和云端PostgreSQL执行一致的通知计算规则。云端场景在回滚事务中验证，生产HTTP验收不向真实用户发布虚构事件。发布后从未登录客户端验证网页、会话、关注和原文；结果记录在上线与验收文档。
